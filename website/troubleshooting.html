Bot Not Receiving Messages

This is the most common issue. Here's how to diagnose and fix it:

Most Common Cause

The companion radio is NOT subscribed to the channels where users are sending messages.

Solution

Open MeshCore App

Use the MeshCore mobile app to configure your companion radio.

Join Channels

Go to Channel Settings and join/subscribe to channels (e.g., #weather, #wxtest).

Restart the Bot

# If running as service
sudo systemctl restart weather_bot

# If running manually
# Press Ctrl+C and restart with:
python3 weather_bot.py

Test

Send wx London from the MeshCore app and watch for the response.

Other Checks

  • Range: Is the sending radio within LoRa range?
  • Power: Is the sending radio powered on?
  • Frequency: Are both radios on the same frequency/band?
  • PSK: Do both radios have matching encryption keys for the channel?

No Serial Port Found

Error: No serial port found

Solutions

1. Check USB Connection

  • Verify the USB cable is securely connected
  • Try a different USB cable (some are power-only)
  • Try a different USB port
  • Ensure the radio is powered on

2. List Available Ports

# Linux
ls /dev/ttyUSB* /dev/ttyACM*

# Windows
# Check Device Manager

# macOS
ls /dev/cu.usbserial-*

3. Specify Port Manually

python3 weather_bot.py --port /dev/ttyUSB0 --baud 115200

4. Check Permissions (Linux)

# Add user to dialout group
sudo usermod -a -G dialout $USER

# Then logout and login again

# Or temporarily:
sudo chmod 666 /dev/ttyUSB0

Location Not Found

Error: Location 'Lndn' not found

Solutions

  • Check spelling: Use correct city name
  • Use full name: "Manchester" instead of "Manc"
  • Add country/region: wx York, UK
  • Try alternate names: Some cities have multiple names

Examples

wx Lndn
Location not found
wx London
London, GB (Weather data...)

Wrong City Returned

Some city names exist in multiple countries (e.g., York in UK and USA).

Problem Example

wx York
York, US (Pennsylvania, USA)

But you wanted York, UK!

Solution 1: Specify Country in Command (Recommended)

wx York UK
York, GB (United Kingdom)

Solution 2: Use Comma Format

wx York, UK

Solution 3: Set Default Country

If most users are in one country:

# Prefer UK cities by default
python3 weather_bot.py --country GB

# Prefer US cities by default
python3 weather_bot.py --country US

Service Won't Start

sudo systemctl status weather_bot
Active: failed

Common Causes and Fixes

1. User Does Not Exist (Exit Code 217)

# Check current user
whoami

# Edit service file to match your username
sudo nano /etc/systemd/system/weather_bot.service
# Change User=pi to User=yourusername

sudo systemctl daemon-reload
sudo systemctl restart weather_bot

2. Path Does Not Exist

# Verify paths in service file
ls /home/pi/MCWB/weather_bot.py

# Update WorkingDirectory and ExecStart paths
sudo nano /etc/systemd/system/weather_bot.service

sudo systemctl daemon-reload
sudo systemctl restart weather_bot

3. Python Not Found

# Check Python path
which python3

# Update ExecStart in service file if needed
sudo nano /etc/systemd/system/weather_bot.service

4. View Detailed Logs

# View service logs
sudo journalctl -u weather_bot -n 50

# Follow logs in real-time
sudo journalctl -u weather_bot -f

Automated Fix

Use the installation script to automatically configure everything:

# Remove old service
sudo systemctl stop weather_bot 2>/dev/null || true
sudo systemctl disable weather_bot 2>/dev/null || true
sudo rm /etc/systemd/system/weather_bot.service 2>/dev/null || true
sudo systemctl daemon-reload

# Reinstall
cd ~/MCWB
./install_service.sh

Using Debug Mode

Debug mode shows detailed information about bot operation:

python3 weather_bot.py --debug

What You'll See

Startup Messages

[2026-02-24 13:28:49] MeshCore [WX_BOT]: LoRa connected on /dev/ttyUSB0 at 115200 baud
[2026-02-24 13:28:49] MeshCore [WX_BOT]: MeshCore started
Weather Bot started. Send 'wx [location]' to get weather.

Message Received

[2026-02-24 13:30:15] MeshCore [WX_BOT]: Binary frame: CHANNEL_MSG_V3 on channel_idx 2
[2026-02-24 13:30:15] MeshCore [WX_BOT]: LoRa RX channel msg from USER1 on channel_idx 2: wx London
[2026-02-24 13:30:15] WeatherBot: Processing message from USER1: wx London
[2026-02-24 13:30:15] WeatherBot: Weather request for location: London

Weather Response

[2026-02-24 13:30:16] WeatherBot: Replying on channel_idx 2: Weather for London, GB...

Debugging Tips

  • Look for "Binary frame: CHANNEL_MSG" to confirm messages are arriving
  • Check "channel_idx" values to understand channel routing
  • Search for "Error" or "Warning" keywords in logs
  • Verify "Weather request for location" appears for valid commands

Internet Connection Issues

Test API Access

# Test without radio
python3 weather_bot.py --location London

# Test API directly
curl "https://api.open-meteo.com/v1/forecast?latitude=51.5074&longitude=-0.1278¤t_weather=true"

Symptoms

  • Bot receives commands but doesn't respond
  • Timeout errors in logs
  • Connection refused errors

Solutions

  • Check internet connectivity: ping 8.8.8.8
  • Check DNS resolution: ping api.open-meteo.com
  • Verify firewall isn't blocking outbound HTTPS
  • Check proxy settings if behind a proxy

Performance Issues

High CPU Usage

The bot should use minimal CPU. If you see high usage:

  • Check for rapid message loops (bot responding to itself)
  • Verify no conflicting bot instances are running
  • Check system resources: top or htop

High Memory Usage

Normal usage is < 50MB. If higher:

  • Restart the bot
  • Check for log file size (rotate logs if needed)
  • Monitor with: ps aux | grep weather_bot

Common Error Messages

"Module not found" Errors

Error: requests not found. Install with: pip install requests

Fix:

pip install -r requirements.txt

"Permission denied" on Serial Port

PermissionError: [Errno 13] Permission denied: '/dev/ttyUSB0'

Fix:

# Add user to dialout group
sudo usermod -a -G dialout $USER
# Logout and login for changes to take effect

# Or temporarily:
sudo chmod 666 /dev/ttyUSB0

"Connection refused" to Weather API

ConnectionError: Connection refused to api.open-meteo.com

Fix:

  • Check internet connection
  • Verify DNS is working
  • Check firewall settings

Web Dashboard Issues

Dashboard Not Loading

Check if Flask is installed:

pip install Flask

Port Already in Use

OSError: [Errno 48] Address already in use

Fix:

# Use a different port
python3 web_dashboard.py --port 8080

# Or find and kill the process using port 5000
lsof -ti:5000 | xargs kill

Cannot Access from Another Device

Ensure you're using the network host option:

python3 web_dashboard.py --host 0.0.0.0

Check firewall:

# Allow port 5000 through firewall
sudo ufw allow 5000

When Opening an Issue

Include the following information:

  1. Debug logs: Run with --debug and save output
  2. Command used: Exact command that triggered the issue
  3. Platform: OS, Python version, hardware
  4. Radio info: MeshCore firmware version, radio model
  5. Steps to reproduce: Clear steps to recreate the issue

Capture Debug Logs

# Save debug output to file
python3 weather_bot.py --debug 2>&1 | tee debug.log

# For service:
sudo journalctl -u weather_bot -n 200 > service_debug.log
