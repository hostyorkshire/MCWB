Weather API (Open-Meteo)

The bot uses the free Open-Meteo API for weather data.

No API Key Required

Open-Meteo is completely free and doesn't require registration or API keys. It's perfect for hobby and personal projects.

API Endpoints

Endpoint Purpose
https://geocoding-api.open-meteo.com/v1/search Geocoding - Convert location names to coordinates
https://api.open-meteo.com/v1/forecast Weather data - Current conditions and forecasts

Example Request

# Geocoding request
GET https://geocoding-api.open-meteo.com/v1/search?name=London&count=1

# Weather request
GET https://api.open-meteo.com/v1/forecast?latitude=51.5074&longitude=-0.1278¤t_weather=true&hourly=apparent_temperature,relative_humidity_2m,wind_speed_10m,wind_direction_10m,precipitation

Weather Data Parameters

Parameter Description
latitude Latitude in decimal degrees
longitude Longitude in decimal degrees
current_weather Include current weather conditions
hourly Hourly parameters (apparent_temperature, humidity, wind, etc.)

MeshCore Protocol

The bot implements the MeshCore companion radio binary protocol for USB serial communication.

Protocol Reference

Full protocol documentation: MeshCore Companion Radio Protocol

Frame Structure

Byte Description
0 Frame start byte (0x3E for radio→app, 0x3C for app→radio)
1 Command code
2-3 Payload length (little-endian uint16)
4+ Payload data

Command Codes

Code Name Direction Description
0x01 CMD_APP_START → radio Initialize session on connect
0x03 CMD_SEND_CHAN_MSG → radio Send a channel text message
0x05 CMD_GET_DEVICE_TIME ← radio Radio requests current time
0x08 RESP_CHANNEL_MSG ← radio Channel message received (older format)
0x09 RESP_CURR_TIME → radio Response with current time
0x0A CMD_SYNC_NEXT_MSG → radio Request next queued message
0x11 RESP_CHANNEL_MSG_V3 ← radio Channel message received (V3, includes SNR)
0x83 PUSH_MSG_WAITING ← radio Push: New message queued
0x88 PUSH_CHAN_MSG ← radio Push: Inline channel message

Channel Message Format

V3 Format (0x11):

Offset Size Field
0 1 Code (0x11)
1 1 SNR (signal-to-noise ratio)
2-3 2 Reserved
4 1 Channel index (0-7)
5 1 Path length
6 1 Text type
7-10 4 Timestamp (Unix epoch, little-endian)
11+ var Message text (UTF-8)

Python API

The bot is built on the meshcore.py library.

Basic Usage

from meshcore import MeshCore, MeshCoreMessage

# Create instance
mesh = MeshCore("my_node")

# Register message handler
def message_handler(message: MeshCoreMessage):
    print(f"Received: {message.content}")
    if message.channel_idx is not None:
        print(f"Channel index: {message.channel_idx}")

mesh.register_handler("text", message_handler)

# Start listening
mesh.start()

# Send a message
mesh.send_message("Hello!", "text", channel_idx=1)

# Stop when done
mesh.stop()

MeshCoreMessage Object

Property Type Description
sender str Sender username
content str Message text
message_type str Message type ("text", etc.)
channel str or None Channel name
channel_idx int or None Channel index (0-7)
timestamp int Unix timestamp

Sending Messages

# Send on channel index
mesh.send_message("Weather update!", "text", channel_idx=1)

# Send on named channel
mesh.send_message("Weather update!", "text", channel="weather")

# Broadcast (no channel)
mesh.send_message("General message", "text")

Channel Filtering

# Filter to specific channel
mesh.set_channel_filter("weather")

# Listen to all channels (default)
mesh.set_channel_filter(None)

class CustomBot:
    def __init__(self):

        self.mesh.register_handler("text", self.handle_message)

        # Custom logic here
        if message.content.lower().startswith("wx "):

            weather = self.fetch_weather(location)
            self.mesh.send_message(
                weather,
                "text",
                channel_idx=message.channel_idx
            )
    
    def fetch_weather(self, location):
        # Your weather logic
        pass
    
    def start(self):
        self.mesh.start()
    
    def stop(self):
        self.mesh.stop()

Rate Limiting

The Open-Meteo API has usage limits:

  • Free tier: 10,000 requests per day
  • Rate limit: 600 requests per minute

The bot makes 2 API calls per weather request (geocoding + weather data). For typical mesh networks, these limits are more than sufficient.

Error Handling

The bot includes comprehensive error handling:

Error Type Bot Response
Location not found "Sorry, I couldn't find that location."
API unavailable "Sorry, weather data is currently unavailable."
Network timeout Logged, no response sent
Serial port error Logged, connection retry attempted

Security Considerations

Channel Encryption

  • Hashtag channels (1-7) use unique PSKs for encryption
  • Only devices with correct PSK can decrypt messages
  • Channel 0 typically uses well-known PSK (public channel)

API Safety

  • Bot only queries public weather API
  • No user data sent to API (only location names)
  • No authentication credentials stored

Input Validation

  • Location inputs are validated before API calls
  • Invalid channel indices are filtered
  • Malformed messages are ignored gracefully
